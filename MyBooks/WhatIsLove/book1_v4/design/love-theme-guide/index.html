The Love Theme

The visual system for What Is Love? God's Perfect Love. Two variants — Red and Blue — each in light and dark. Four palettes, one grammar.

This document is the specification, rendered in the theme it describes. Use the switcher above to move between all four palettes; every example on the page re-renders live, so nothing here is an approximation.

One · The two variants

Red is the cover: Burnt Crimson and Gold Torch. Passion, sacrifice, the blood of the martyrs, the Cross. It is the book's primary identity and the default.

Blue is the older and quieter half of the same tradition: lapis and gold, the pigment reserved for the Blessed Virgin because ultramarine cost more than gold itself. Marian blue carries fidelity, covenant, and constancy — the calm inside the same doctrine.

They are not moods to pick between at whim. Red is the default for the book proper; Blue is for Marian material, covenant chapters, liturgical-season work, and any surface that should feel adjacent to the book without competing with it. Gold is common to both, which is what makes them read as one system rather than two.

Why gold in both
Gold is not decoration in either variant. In sacred art it signifies uncreated light — the thing that does not belong to the created palette. Holding it constant across red and blue is the visual claim that both are lit from the same source.

Two · Light and dark are not mirrors

The most important rule in the system, and the one most likely to be broken by accident.

Gold cannot be text on a light ground. Gold Torch #be985c measures 2.44:1 on the red cream and 2.39:1 on the blue paper — far below any usable threshold. On both dark grounds it is comfortably legible. So gold's role changes, and the tokens encode it:

Correct

  • --accent is text-safe in all four palettes. Every label, eyebrow, small-caps run, table header.
  • --ornament is always true Gold Torch. Rules, borders, fills, flourishes — surfaces with no text on them.
  • Ask "is this text?" If yes, --accent. If no, --ornament.

Wrong

  • Hard-coding #be985c anywhere at all.
  • Using --ornament for text because it looked right in dark mode.
  • Using a gold rule to carry information on a light ground — decorative only, since it cannot reach 3:1.

Light is the default. Dark grounds cause halation — the bloom around light glyphs — which is worse for readers with astigmatism. Dark mode is offered, not assumed. Dark body ink is deliberately not white: maximum contrast is not maximum legibility, and WCAG sets a floor, not a ceiling.

Four · Every element

You were right that the first draft skipped this. Bare tags were unstyled, which meant any plain HTML — a pasted chapter, a Markdown conversion, anything generated by a tool — fell back to browser defaults and broke the system. Every element below is now styled by tag, so correct HTML is correctly rendered with no classes at all.

A correction to v1.0
v1.0 said "headings are classes, not tag selectors." That was over-cautious. Tags now carry sensible defaults so plain HTML works out of the box, and the utility classes remain as overrides for the case where semantic level and visual size need to differ — an <h3> that must look like a chapter opener gets class="chapter-title". Tags for defaults, classes for exceptions.

The Definition

Canonical · do not alter
God's Perfect Love is the sacred gift of covenant which binds truth, justice, mercy and sacrifice into life-giving communion.

No Oxford comma. "sacrifice", never "sacrificial". The four are co-equal — no styling may emphasise one.

On IDs

The system defines no styling on IDs, deliberately. IDs outrank classes in specificity, which makes them hard to override, and they cannot repeat, which makes them useless for anything reusable. They have two jobs here, both structural:

  • Anchors — id="ch-07", id="pillar-mercy". Lowercase, hyphenated, prefixed by kind.
  • Accessibility wiring — aria-labelledby, aria-describedby, <label for>.

Script hooks should use data- attributes, as the variant switcher above does.

Seven · Applying the theme

<html lang="en" class="love love--red love--light">
  <link rel="stylesheet" href="love-theme.css">
  <body><div class="page"> … </div></body>
</html>

Both axes are independent: pick one of --red/--blue and one of --light/--dark. Write both explicitly rather than relying on a default, so a document's appearance is never ambiguous.

Migration from memory.css. Card variants, tables, tags, TOC, and stats were named to match what exists there, so memory.html should convert by swapping the stylesheet link and adding class="love love--red love--dark" to the root, then removing any surviving hard-coded hexes.

Eight · Standing rules

Always

  • Reference tokens, never hex values.
  • Write correct semantic HTML — the tag styling assumes it.
  • Give every colour-coded state a text label or glyph as well.
  • Use --accent for text, --ornament for everything else.
  • Re-run the contrast table after any token change, across all four palettes.
  • Quote Scripture from the RSV.
  • Reproduce the definition verbatim, with no Oxford comma.

Never

  • Set type below weight 400, or track body text.
  • Use Cinzel Decorative below 1.4rem or for body copy.
  • Put long-form reading or a redline on pure white.
  • Let one of the four pillars read as larger, brighter, or first.
  • Style anything via an ID.
  • Add a shadow, a gradient, or a radius above 3px. This is a book.
  • Mix red and blue tokens in one document.
